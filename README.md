# PDF Mail Deliver

目前版本：**16.1.0**

Windows 桌面工具，用來批次拆分薪資、鐘點費或加班費通知單 PDF，擷取姓名與 Email，產生寄件清單，透過教育雲信箱寄送個別附件。

## 功能

- 多個 PDF 批次拆分；支援 Email 換行與全形符號。
- 產生或匯入預計寄件清單，成功後從待寄清單移除。
- 針對 `Server not connected` 自動重試，沿用原 PDF、標題與內文。
- 可設定執行時限，初始預設 **24 小時**；使用者修改後自動儲存，下次開啟沿用。
- 顯示等待倒數，可停止寄送或等待。
- 一小時內成功寄送達 100 封時，每封間隔至少 37 秒。

## 安裝與啟動

需要 Python 3.10 以上（含 tkinter）及以下套件：

```powershell
python -m pip install pdfplumber pypdf
python pdfmailDeliver.py
```

也可以執行 `啟動.bat`，先檢查 GitHub 更新再啟動程式；`更新.bat` 只執行更新。
批次檔使用 PATH 上的 `python`，請確認套件安裝在同一個 Python 環境。
更新依 `update.json` 下載檔案，原有程式備份在 `_update_backup/`；本機帳號與時數設定不在更新清單內。

## 操作方式

1. 設定每封信間隔與「持續執行上限」。時數可填正小數；空白、零、負數或非有限值不會覆蓋已儲存設定。
2. 選擇原始 PDF，拆分並產生清單；或匯入「預計寄件清單」直接使用既有 PDF。
3. 確認收件清單與附件後，輸入寄件帳號、密碼，按「確定寄送」。
4. 程式開始寄送並計算執行時限；若存在符合條件的失敗項目，依下列規則重試。
5. 可按「停止寄送／等待」。停止或達時限後，未完成項目仍保留在清單中。

## 自動重試規則

只重試當次作業失敗原因包含 `Server not connected` 的項目，不分大小寫；其他錯誤保留在失敗清單，不自動重試。

| 連續無成功時的重試次數 | 等待時間 |
| --- | --- |
| 1 | 2 分鐘 |
| 2 | 4 分鐘 |
| 3 | 8 分鐘 |
| 4 | 16 分鐘 |
| 5 | 32 分鐘 |
| 6 | 64 分鐘 |
| 7 及以後 | 120 分鐘 |

- 等待時間從上一輪寄送結束後計算。任一封成功，下一次等待重設為 2 分鐘。
- 重試使用當次準備好的 PDF 路徑、標題與內文，不再切割 PDF；執行期間請勿移動或修改附件。
- 已成功的項目不再寄送；沒有符合條件的失敗項目時提早結束。
- N 小時包含首次寄送、每封間隔與重試等待，從開始寄送計算。
- 時限到或按停止後，不開始下一封；已進行中的 SMTP 操作完成後才停止。SMTP socket timeout 為 30 秒，並非整封交易的絕對總時限。
- 執行期間需保持程式開啟、電腦清醒及網路連線。關閉或重開不會自動恢復上一輪重試計時；可匯入剩餘的預計寄件清單再次開始。
- 附件不存在時取消該封寄送。SMTP 已接受郵件後，關閉連線失敗不再把該封誤判為寄送失敗。

## 檔案與設定

程式目錄中的主要檔案：

- `拆分_時間戳記/`：拆分後 PDF。
- `預計寄件清單_時間戳記.txt`：待寄項目，成功項目會移除；全數寄出後刪除空清單。
- `失敗清單_時間戳記.txt`：每封更新的未完成項目，包含失敗原因或「尚未寄送」；全數成功時內容為空。
- `寄送資訊.log`：歷次寄送結果。
- `.user_config`：帳號、編碼後密碼、路徑、寄送間隔及 `retry_hours` 時數設定。

預計寄件清單以 Tab 分隔：

```text
相對路徑<Tab>Email<Tab>原始檔名
```

相對路徑以程式目錄為基準。重新匯入時需保留對應附件位置。失敗清單是結果報告，不是可匯入的預計寄件清單。

密碼僅以 Base64 編碼，並非加密；請勿公開 `.user_config`、收件清單、寄送記錄或 PDF。這些執行產物已加入 `.gitignore`。

## SMTP

預設伺服器為 `mail.edu.tw`，SSL 連線埠 `465`。若改用其他服務，請調整程式常數。

## 測試

```powershell
python -m unittest test_retry -v
```

測試採模擬 SMTP 與虛擬時間，不寄送真實郵件；包含倍增與上限、成功重設、錯誤篩選、時限、停止、附件與信件內容沿用、QUIT 錯誤處理，以及 Tk 介面與時數設定保存。介面測試需要桌面環境。
